## 顺序与验收

1. 上游与环境：核实远程 URL、提交、历史和代码，记录哈希；确认上游工作区无修改。
2. 数据：流式导入 SQLite；以目标域全局时间截点限制所有源域训练数据；只从训练数据建立用户群、物品表和门控统计。输出划分与覆盖率，明确有界试运行与全量数据的区别。
3. 模型：上游 GAT 提取源域知识，MLP 映射并扩展目标域图；独立本地预测加迁移预测，新增 gamma 模块。源知识冻结，不可用时回退。固定和动态权重使用相同范围。
4. 联邦模拟：沿用上游的用户客户端、域服务器组织方式，客户端更新后聚合共享模块与触及物品；用户表示保留在模拟客户端状态。该初始协议不代表项目必须永远采用此客户端定义。
5. 评估：固定训练候选物品表，屏蔽训练正样本，计算完整候选集 Recall@10、NDCG@10；只按验证集选择检查点，每个候选方法最终测试一次。
6. 验证：检查门控梯度和输入条件、缺失源信息回退、训练时间边界、重复交互处理、负采样排除训练正样本、聚合以及排序指标。对本地真实 CSV 的小规模子集运行全部已实现对照，保存运行汇总。
